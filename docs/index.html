ConectividadeESP32

WiFi e MQTT para ESP32 sem travar o seu loop(). Reconecta sozinha, guarda as mensagens enquanto está offline, conecta na AWS com certificados no LittleFS e tem um portal para escolher a rede WiFi pelo celular.

WiFi and MQTT for the ESP32 without blocking your loop(). It reconnects on its own, queues messages while offline, connects to AWS with certificates stored in LittleFS and ships a portal to pick the WiFi network from your phone.

Início rápidoQuick start

Um ESP32 que conecta no WiFi, publica a cada 5 segundos e recebe comandos — sem nenhum delay().

An ESP32 that joins WiFi, publishes every 5 seconds and receives commands — without a single delay().

cpp
#include <ConectividadeESP32.h>

const char* TOPICOS_PUB[] = { "casa/sala/temperatura" };   // índice 0
const char* TOPICOS_REC[] = { "casa/sala/comando" };       // índice 0
ConfigTopicos topicos = { TOPICOS_PUB, 1, TOPICOS_REC, 1 };

uint32_t ultimoEnvio = 0;

void setup() {
    configurarDebug(DEBUG_INFO);

    conectividade.registrarCallbackMensagem([](const char* topico, const String& msg) {
        debugInfo(String(topico) + " = " + msg);
    });

    conectividade.beginSimples(
        { "MinhaRede", "minha_senha" },                     // WiFi
        { "192.168.0.10", 1883, "esp32_sala", "", "" },     // broker, porta, clientId, usuário, senha
        topicos);
}

void loop() {
    conectividade.update();                                 // SEMPRE no loop()

    if (millis() - ultimoEnvio >= 5000) {
        ultimoEnvio = millis();
        conectividade.publicar(0, String(temperatureRead(), 1));
    }
}
cpp
#include <ConectividadeESP32.h>

const char* PUB_TOPICS[] = { "home/room/temperature" };   // index 0
const char* SUB_TOPICS[] = { "home/room/command" };       // index 0
TopicsConfig topics = { PUB_TOPICS, 1, SUB_TOPICS, 1 };

uint32_t lastSend = 0;

void setup() {
    configurarDebug(DEBUG_INFO);

    connectivity.onMessage([](const char* topic, const String& msg) {
        debugInfo(String(topic) + " = " + msg);
    });

    connectivity.beginSimple(
        { "MyNetwork", "my_password" },                    // WiFi
        { "192.168.0.10", 1883, "esp32_room", "", "" },    // broker, port, clientId, user, password
        topics);
}

void loop() {
    connectivity.update();                                 // ALWAYS in loop()

    if (millis() - lastSend >= 5000) {
        lastSend = millis();
        connectivity.publish(0, String(temperatureRead(), 1));
    }
}
Regra de ouro

Chame conectividade.update() em todo loop(). É ele que avança o WiFi, o MQTT, o portal e a fila. Evite delay() longos no loop.

Golden rule

Call connectivity.update() on every loop(). It drives WiFi, MQTT, the portal and the queue. Avoid long delay() calls in the loop.

Como funcionaHow it works

O código "tradicional" usa while (WiFi.status() != WL_CONNECTED) delay(500); e fica preso enquanto não há rede: nenhum sensor é lido e nenhum botão responde. Esta biblioteca usa máquinas de estado: a cada update() ela verifica a situação, dá um passo e devolve o controle para o seu programa.

"Traditional" code uses while (WiFi.status() != WL_CONNECTED) delay(500); and gets stuck while there is no network: no sensor is read and no button responds. This library uses state machines: on every update() it checks the situation, takes one step and hands control back to your program.

Um detalhe honesto

O connect() do PubSubClient bloqueia durante o handshake (1–3 s em TLS). A biblioteca limita esse tempo, mas se o seu loop tem tempo crítico, leve isso em conta.

An honest caveat

PubSubClient's connect() blocks during the handshake (1–3 s with TLS). The library caps that time, but take it into account if your loop is time-critical.

Instead of { "Network", "password" }, pass SAVED_WIFI: the library uses the network stored in Preferences and, if there is none, opens the configuration portal.

Structs de configuraçãoConfiguration structs

Todas aceitam inicialização por chaves, na ordem dos campos. Campos com dois nomes (ex.: senha / password) são o mesmo campo. A biblioteca copia os textos, então você pode passar String.c_str() ou variáveis locais. Só os arrays de tópicos precisam ser globais.

All of them accept brace initialization in field order. Fields with two names (e.g. senha / password) are the same field. The library copies the strings, so you may pass String.c_str() or local variables. Only the topic arrays must be global.

Client ID único

Dois dispositivos com o mesmo clientId no mesmo broker ficam derrubando um ao outro. Se deixar vazio, a biblioteca usa ESP32-XXXX (final do MAC).

Unique client ID

Two devices with the same clientId on the same broker keep kicking each other off. If you leave it empty, the library uses ESP32-XXXX (end of the MAC).

Certificados no LittleFSCertificates in LittleFS

O LittleFS é um sistema de arquivos na flash do ESP32, como um pequeno pendrive. Você coloca os arquivos na pasta data/ do projeto e grava todos de uma vez. Nos campos de certificado, basta passar o caminho: a biblioteca abre e lê o arquivo.

LittleFS is a file system on the ESP32 flash, like a tiny USB stick. You put the files in the project's data/ folder and upload them all at once. In the certificate fields, just pass the path: the library opens and reads the file.

Portal de configuração WiFiWiFi configuration portal

O ESP32 cria uma rede própria (modo AP). Ao conectar o celular nela, a página de configuração abre sozinha (captive portal) — ou acesse http://192.168.4.1. A página lista as redes, você escolhe, digita a senha e salva. As credenciais vão para o Preferences e o ESP32 conecta.

The ESP32 creates its own network (AP mode). When your phone joins it, the configuration page opens by itself (captive portal) — or browse to http://192.168.4.1. The page lists networks; you pick one, type the password and save. Credentials go to Preferences and the ESP32 connects.

cpp
#include <ConectividadeESP32.h>

const int PINO_BOTAO = 0;      // BOOT
uint32_t botaoDesde = 0;

void setup() {
    configurarDebug(DEBUG_INFO);
    pinMode(PINO_BOTAO, INPUT_PULLUP);

    // Abre o portal sozinho após 3 falhas seguidas com a rede salva
    conectividade.definirPortalAutomatico(true, "Config-Sala", nullptr, 3);

    conectividade.registrarCallbackPortalSalvo([](const String& ssid) {
        debugInfo("Rede escolhida: " + ssid);
    });

    // WIFI_SALVO: usa a rede salva; sem nenhuma, abre o portal
    conectividade.beginSomenteWiFi(WIFI_SALVO);
}

void loop() {
    conectividade.update();    // também atende o portal

    // BOOT pressionado por 3 s → portal (fecha após 5 min sem uso)
    if (digitalRead(PINO_BOTAO) == LOW) {
        if (botaoDesde == 0) botaoDesde = millis();
        if (millis() - botaoDesde > 3000 && !conectividade.portalAtivo())
            conectividade.iniciarPortalConfiguracao("Config-Sala", nullptr, 300);
    } else {
        botaoDesde = 0;
    }
}
cpp
#include <ConectividadeESP32.h>

const int BUTTON_PIN = 0;      // BOOT
uint32_t pressedSince = 0;

void setup() {
    configurarDebug(DEBUG_INFO);
    pinMode(BUTTON_PIN, INPUT_PULLUP);

    // Open the portal by itself after 3 consecutive failures with the saved network
    connectivity.setAutoConfigPortal(true, "Room-Setup", nullptr, 3);

    connectivity.onPortalSaved([](const String& ssid) {
        debugInfo("Network chosen: " + ssid);
    });

    // SAVED_WIFI: use the saved network; if there is none, open the portal
    connectivity.beginWiFiOnly(SAVED_WIFI);
}

void loop() {
    connectivity.update();     // also serves the portal

    // BOOT held for 3 s → portal (closes after 5 min idle)
    if (digitalRead(BUTTON_PIN) == LOW) {
        if (pressedSince == 0) pressedSince = millis();
        if (millis() - pressedSince > 3000 && !connectivity.isConfigPortalActive())
            connectivity.startConfigPortal("Room-Setup", nullptr, 300);
    } else {
        pressedSince = 0;
    }
}

Comportamentos importantes

• Enquanto o portal está aberto, a biblioteca para de tentar conectar como cliente (trocar de canal derrubaria o celular).

• Depois de salvar, o portal espera 1,5 s (para a página receber a resposta), fecha e conecta.

• Se as credenciais salvas pelo portal falharem 3 vezes, o portal volta — mesmo sem o modo automático.

• O timeout só conta enquanto ninguém está conectado ao AP.

Important behaviour

• While the portal is open, the library stops trying to connect as a station (hopping channels would drop the phone).

• After saving, the portal waits 1.5 s (so the page gets the response), closes and connects.

• If credentials saved through the portal fail 3 times, the portal comes back — even without auto mode.

• The timeout only counts while nobody is connected to the AP.

Preferences (NVS)

O Preferences guarda pares chave → valor na memória não-volátil (NVS) do ESP32. Os dados sobrevivem a desligar, apertar reset e gravar um firmware novo. A biblioteca usa um namespace próprio ("conectividade") e o abre só durante cada leitura ou escrita — seu código continua livre para usar o Preferences com outros namespaces.

Preferences stores key → value pairs in the ESP32 non-volatile storage (NVS). Data survives power-off, reset and flashing new firmware. The library uses its own namespace ("conectividade") and only opens it during each read or write — your code remains free to use Preferences with other namespaces.

cpp
// Credenciais WiFi (o portal faz isso por você)
conectividade.salvarCredenciaisWiFi("Casa", "senha1234");   // senha: 8 a 63 caracteres, ou ""
conectividade.temCredenciaisWiFi();                          // bool
conectividade.apagarCredenciaisWiFi();                       // "esquecer rede"

// Valores do seu projeto (texto, chave com até 15 caracteres)
conectividade.salvarPreferencia("intervalo", "30");
int intervalo = conectividade.lerPreferencia("intervalo", "10").toInt();
conectividade.apagarPreferencia("intervalo");

// Seu próprio namespace convive normalmente
Preferences prefs;
prefs.begin("meuapp", false);
prefs.putUInt("boots", prefs.getUInt("boots", 0) + 1);
prefs.end();

// WiFi credentials (the portal does it for you)

Fila offlineOffline queue

Quando você chama publicar() sem conexão, a mensagem vai para uma fila na RAM. Quando o MQTT volta, o update() envia a fila na ordem (até 10 mensagens por ciclo, para não travar o loop). Online e com a fila vazia, a mensagem é enviada direto.

When you call publish() while disconnected, the message goes into a RAM queue. When MQTT comes back, update() sends the queue in order (up to 10 messages per pass, so the loop is not blocked). When online with an empty queue, messages are sent directly.

DimensionandoSizing

slots = tempo offline a suportar ÷ intervalo entre mensagens. Ex.: 10 min com 1 mensagem a cada 30 s → 20 slots. Memória ≈ slots × (tópico + payload): 20 × (64 + 256) ≈ 6,4 KB.

slots = offline time to survive ÷ interval between messages. E.g. 10 min at one message every 30 s → 20 slots. Memory ≈ slots × (topic + payload): 20 × (64 + 256) ≈ 6.4 KB.

Limites

Tópico ou payload maior que o slot é recusado com erro (nunca cortado). A fila fica na RAM: se a placa reiniciar offline, ela se perde.

Limits

A topic or payload larger than the slot is rejected with an error (never truncated). The queue lives in RAM: if the board reboots while offline, it is lost.
